## 0. Как пользоваться этим документом

1. Создайте пустую папку проекта, например `veta-game`.
2. Положите в неё этот файл под именем `SPEC.md`.
3. Откройте папку в Claude Code и отправьте первый промпт из раздела 14.
4. Работайте по этапам из раздела 12. После каждого этапа Claude Code должен показать результат и объяснить, как его посмотреть.

Заказчик не читает и не правит код. Поэтому Claude Code обязан:

- объяснять каждый шаг простым языком, без жаргона;
- давать запуск одной командой и писать в `README.md` пошаговую инструкцию «для человека»;
- после каждого этапа явно говорить, что проверить глазами и что нажать;
- не задавать технических вопросов, на которые можно принять разумное решение самостоятельно. Принятые решения фиксировать в `DECISIONS.md`.

## 1. Цель и контекст

**Что это.** Браузерный 2D-платформер в фирменном стиле Экспертной группы VETA. Главный герой — технический директор VETA Александр Терентьев в образе прораба-эксперта. Он проходит стройку и срывает «овечьи шкуры» с волков — недобросовестных участников строительства.

**Зачем.**

- Основная цель — демонстрация руководству VETA возможностей Claude Code: рабочая игра, собранная быстро и без программиста.
- Вторичная цель — прототип маркетингового инструмента: игра для сайта, конференций и Telegram, которая подводит юристов и заказчиков строительства к обращению в VETA.

**Ключевая метафора.** «Волк в овечьей шкуре». Снаружи всё выглядит нормально, а под шкурой скрыт дефект, завышенный объём или отсутствующий документ. Экспертиза снимает шкуру.

**Целевая аудитория финальной версии.** Корпоративные юристы, заказчики и девелоперы, подрядчики, участники строительных споров.

**Что должен вынести игрок:**

1. В строительном споре решают документы.
2. Скрытые дефекты находятся экспертизой.
3. Досудебную экспертизу выгодно сделать заранее.
4. Если заключение оппонента вызывает сомнения, есть рецензия и повторная экспертиза.

## 2. Технический стек и формат результата

| Параметр | Требование |
|---|---|
| Движок | Phaser 3, последняя стабильная 3.x. Версию зафиксировать точно |
| Язык | JavaScript (ES-модули). TypeScript не нужен |
| Сборка | Vite + `vite-plugin-singlefile` |
| Итоговый артефакт | **Один файл `dist/index.html`**. Вся графика, звук и код внутри, открывается двойным кликом без интернета |
| Разрешение | Логическое 960×540, масштабирование `Phaser.Scale.FIT` с сохранением пропорций |
| Платформы | Десктоп (Chrome, Edge, Safari, Firefox) и мобильные браузеры (iOS Safari, Android Chrome) |
| Производительность | Стабильные 60 FPS на среднем ноутбуке, без провалов ниже 30 FPS на смартфоне 3-летней давности |
| Размер | `dist/index.html` не больше 5 МБ |
| Внешние запросы | **Никаких** в итоговом файле: ни CDN, ни шрифтов из интернета, ни аналитики. Шрифты встраиваются в файл |
| Графика | Пиксель-арт, генерируется кодом или рисуется программно в PNG-спрайтшиты скриптами в `tools/`. Сторонние ассеты допустимы только с лицензией CC0, источник указать в `CREDITS.md` |
| Звук | Простые звуки, сгенерированные кодом (WebAudio или jsfxr-подобный генератор). Фоновая музыка необязательна. Кнопка «звук вкл/выкл» обязательна |

Команды в `package.json`:

- `npm run dev` — запуск для разработки с автообновлением;
- `npm run build` — сборка одного файла `dist/index.html`;
- `npm run sprite` — генерация спрайта героя из фото (см. 4.1).

## 3. Фирменный стиль

Источник: «Руководство по фирменному стилю VETA», бюро Flavita, 09.2019. В 2025 году логотип обновлялся. **Перед финальной сборкой палитру и логотип сверить с актуальными файлами дизайнера** (открытый вопрос, раздел 13).

### 3.1 Палитра (токены в `src/brand.js`)

| Токен | HEX | Назначение по брендбуку | Применение в игре |
|---|---|---|---|
| `blueDeep` | `#024F99` | Насыщенный синий, основной фон носителей | Фон меню, экраны, небо уровней (с затемнением) |
| `blue` | `#0C5EAA` | Синий | Платформы, интерфейс, подсветка |
| `red` | `#E51A3C` | Карминово-красный, только «галочка» и акценты | Чекпоинты-«галочки», луч уровня, урон, CTA-кнопки. **Не заливать красным большие площади** |
| `black` | `#1A1A1A` | Текст, статус логотипа | Контуры, текст на светлом |
| `gray` | `#E5E5E4` | Элементы на белом | Бетон, подложки, рамки на светлом фоне |
| `white` | `#FFFFFF` | — | Текст на синем |

Для пиксель-арта допускаются производные оттенки (светлее или темнее базовых на 10–30 %). Их тоже хранить в `brand.js`, а не прямо в коде сцен.

### 3.2 Шрифты

- Фирменный шрифт — Museo Sans Cyrl (заголовки 900/700, текст 300/500). Он платный. Если заказчик передаст файлы шрифта с лицензией на веб-использование, встроить их.
- До этого использовать свободную замену с кириллицей и лицензией OFL (например, Manrope) с теми же ролями: жирный для заголовков, regular для текста. Подключение шрифта сделать через один токен, чтобы замена занимала одну строку.
- Для мелких игровых счётчиков допускается пиксельный шрифт с кириллицей (OFL).

### 3.3 Фирменный идентификатор: угловые рамки

Используются на всех экранах меню, в диалогах и на финальном экране:

- на синем фоне красные уголки строго в **правом верхнем и левом нижнем** углах, синие (`blue`) — в левом верхнем и правом нижнем;
- на светлом фоне все уголки серые;
- отступ рамки от края равен толщине линии рамки.

Сделать переиспользуемый компонент `CornerFrame`.

### 3.4 Логотип и название

- Логотип **не перерисовывать**. Использовать только официальный файл (SVG/PNG), который передаст заказчик, и класть его в `assets/brand/`. До этого ставить текстовую заглушку «VETA».
- Логотип показывать только на титульном и финальном экранах, на спокойном фоне, с охранным полем, без искажения пропорций, обводок и рамок.
- Название пишется «Экспертная группа VETA» латиницей и без кавычек. Сокращение «ЭГ» запрещено, в тексте допускается просто VETA.

### 3.5 «Галочка» как игровой знак

Красная «галочка» из логотипа — сквозной игровой символ «проверено экспертом»: чекпоинты, отметка о собранном документе, значок победы над волком. Рисовать её как простую стилизованную галку в пиксель-арте, **не копируя** логотип целиком.

## 4. Персонажи

### 4.1 Герой: Терентьев-прораб

- **Образ:** белая каска, жилет, планшет под мышкой, лазерный нивелир в руке. Спокойный и ироничный.
- **Спрайт:** 32×48 px. Анимации: idle (2 кадра), бег (6), прыжок (2), выстрел лучом (2), урон (1), победа (2).
- **Голова из фото.** Скрипт `tools/make_sprite.py` (Python + Pillow) берёт фото `assets/source/terentyev.jpg`, кадрирует лицо, уменьшает до 12–16 px по ширине и квантует в фирменную палитру плюс 3–4 оттенка кожи. Результат накладывается на тело-шаблон. На выходе — PNG-спрайтшит в `assets/sprites/`.
- **Согласие А. Терентьева на использование образа получено.** Портрет включён по умолчанию (флаг `USE_PORTRAIT = true` в `src/config.js`). Обезличенный «Прораб» остаётся запасным вариантом: он нужен, пока фото не загружено в `assets/source/`, и включается той же строкой.
- Если файла `assets/source/terentyev.jpg` нет, сборка не падает: игра автоматически использует обезличенного героя и пишет об этом в консоли.
- **Портрет для диалогов:** 96×96 px, получается тем же скриптом с другими параметрами.

### 4.2 Волки в овечьих шкурах (враги)

| Тип | Поведение | Как побеждается |
|---|---|---|
| **Волк-субподрядчик** | Ходит туда-обратно по платформе. В шкуре неуязвим и выглядит как безобидная овца | Луч нивелира срывает шкуру (анимация: шерсть разлетается), после этого волк уязвим на 3 с. Прыжок сверху выводит его из игры |
| **Волк-сметчик** | Стоит на месте и бросает «пухлые сметы» (снаряды по дуге) | Сорвать шкуру и прыгнуть сверху |
| **Волк-маскировщик** | Прячется в отделке; виден только край хвоста | Луч проявляет его, затем как у субподрядчика |

Побеждённый волк не «умирает». Он убегает за край экрана с табличкой «Претензия принята». Никакой крови и жестокости.

### 4.3 Добросовестные овцы (не враги)

Обычные овцы-рабочие ходят по уровню. Если попасть в такую овцу лучом, она покажет «галочку» и бейдж «Чисто!». Очки не снимаются, но счётчик «ложных подозрений» растёт и выводится в итоге. Смысл: экспертиза нужна, чтобы отличать одних от других, а не нападать на всех.

### 4.4 Босс: Главный волк — генподрядчик

- Огромный волк в костюме из овечьей шерсти с щитом «Заключение-пустышка».
- **Фаза 1:** бросает сметы и акты, призывает двух субподрядчиков.
- **Фаза 2:** щит снимается только если у игрока собран **полный пакет документов** (см. 5.3). При полном пакете появляется кнопка-действие «Ходатайство о повторной экспертизе». Щит рассыпается, луч срывает шкуру.
- Если пакет неполный, Терентьев говорит в баббле: «Без документов суд нас не услышит. Вернёмся за актами». Игрок возвращается к последнему чекпоинту и может дособрать документы. Уровни после чекпоинта не сбрасываются.

### 4.5 NPC

- **Заказчик** (обезличенный девелопер) — даёт вводную в начале.
- **Юрист заказчика** — комментирует важность документов между уровнями.

Реальные имена, кроме Терентьева, не использовать.

## 5. Игровой процесс

### 5.1 Управление

| Действие | Клавиатура | Сенсор |
|---|---|---|
| Движение | ← → / A D | Экранные кнопки слева |
| Прыжок | Пробел / W / ↑ | Кнопка справа |
| Луч нивелира | X / J | Кнопка справа |
| Пауза | Esc / P | Кнопка в углу |

Экранные кнопки появляются автоматически на сенсорных устройствах. Должны работать прыжок «с запасом» (coyote time ~100 мс) и буфер нажатия прыжка (~100 мс), чтобы управление прощало мелкие ошибки.

### 5.2 Луч нивелира

- Горизонтальный красный луч на ~6 тайлов, перезарядка 0,6 с.
- Срывает шкуры с волков.
- Проявляет **скрытые дефекты**: специальные тайлы, которые выглядят как обычная отделка. После проявления дефект показывается с подписью («Пустота под стяжкой», «Трещина в колонне», «Нет гидроизоляции»), начисляются очки и пополняется счётчик дефектов. Часть дефектов опасна до проявления: проваливающийся пол или течь.

### 5.3 Документы (главный предмет сбора)

На каждом уровне 3–4 документа. Собранный документ появляется в «папке дела» в интерфейсе (иконки сверху).

| Документ | Уровень |
|---|---|
| Акт освидетельствования скрытых работ | 1 |
| Исполнительная схема | 1 |
| Общий журнал работ | 1 |
| Договор подряда и приложения | 2 |
| КС-2 (акт о приёмке выполненных работ) | 2 |
| КС-3 (справка о стоимости) | 2 |
| Переписка и претензии | 3 |
| Фотофиксация | 3 |
| Нотариальный протокол осмотра | 3 (бонусный, в труднодоступном месте) |

- **Ворота суда** в конце уровней 1–2 открываются только при минимуме документов (2 из 3 на уровне 1, 3 из 4 на уровне 2).
- **Полный пакет** для победы над боссом — не меньше 7 из 9 документов.
- При подборе каждого документа на 2 секунды всплывает короткая подсказка «зачем он нужен» (тексты в `content/ru.json`, см. раздел 7).

### 5.4 Здоровье, чекпоинты, счёт

- Здоровье — 3 каски. Урон: контакт с волком без шкуры сбоку, снаряды, провалы.
- Чекпоинты — красные «галочки» на шесте. При активации: звук и анимация.
- После потери всех касок — рестарт с последнего чекпоинта. Документы, собранные до чекпоинта, сохраняются.
- **Счёт:** волки ×100, дефекты ×150, документы ×200, время-бонус. «Ложные подозрения» не отнимают очков, а выводятся отдельно на финальном экране.

### 5.5 Сложность

Целевая длительность прохождения 7–10 минут для человека, который почти не играет. Первый уровень обучающий, в нём нельзя погибнуть от падения в яму. Есть режим «Лёгкий» (5 касок, ворота открываются при любом числе документов). Выбирается на титульном экране, по умолчанию — «Обычный».

## 6. Уровни

Тайловые карты собираются в коде или в формате Tiled JSON (на усмотрение Claude Code). Размер тайла 16×16. Длина уровня — примерно 6–8 экранов по горизонтали.

### Уровень 1. «Котлован» (обучение)

- **Окружение:** котлован, опалубка, арматура, лужи. Палитра: серый бетон, синее вечернее небо.
- **Обучение:** подсказки с клавишами появляются по ходу движения (бег, прыжок, луч, документы, чекпоинт).
- **Враги:** 3 волка-субподрядчика, 1 маскировщик.
- **Скрытые дефекты:** пустоты под фундаментной плитой, отсутствие гидроизоляции.
- **Финал:** Ворота суда.

### Уровень 2. «Каркас»

- **Окружение:** монолитный каркас, строительные леса, крюки крана как движущиеся платформы, лифтовая клеть.
- **Враги:** субподрядчики, 2 сметчика.
- **Скрытые дефекты:** трещины в колоннах, оголённая арматура, отклонение от вертикали.
- **Особенность:** участок со «сметными стенами». Стены из бумаги с надписью «Объём завышен» разрушаются лучом и открывают короткий путь.

### Уровень 3. «Сдача объекта» + босс

- **Окружение:** отделка, свежая плитка, коридоры с гипсокартоном.
- **Механика подтопления:** через 40 с после старта снизу начинает медленно подниматься вода. Можно остановить, найдя и «проявив» лучом дефект трубы. Тогда появляется подсказка о фиксации причин подтопления.
- **Враги:** маскировщики в отделке.
- **Бонус:** нотариальный протокол осмотра.
- **Арена босса** в конце уровня (см. 4.4).

## 7. Сюжет и тексты

Все тексты хранятся в `content/ru.json`, не в коде. Тексты ниже — **черновики**. Перед публикацией их согласует А. Терентьев. В файле пометить каждый ключ полем `"status": "draft"`.

### 7.1 Вступление (комикс из 3–4 кадров с диалогами)

1. **Заказчик:** «Объект сдали, а через месяц подвал затопило. Подрядчик говорит — всё по проекту. Документы у него в порядке… вроде бы».
2. **Терентьев:** «"Вроде бы" — это шкура. Посмотрим, что под ней».
3. **Юрист:** «Если пойдём в суд, нам нужна доказательная база».
4. **Терентьев:** «Тогда собираем документы и проверяем каждый метр. Начнём с котлована».

### 7.2 Карточки «Совет эксперта» между уровнями

Короткие экраны в угловых рамках, 2–3 предложения, кнопка «Дальше».

- **После уровня 1:** «Споры на стройке чаще всего упираются в документы. Нет акта скрытых работ — доказать, что было под стяжкой, почти невозможно».
- **После уровня 2:** «Досудебная строительно-техническая экспертиза фиксирует результат работ, пока стороны ещё договариваются. Это дешевле суда».
- **Перед боссом:** «Если заключение эксперта оппонента вызывает сомнения или содержит противоречия, его можно оспорить рецензией и ходатайством о повторной экспертизе».

### 7.3 Финал

- **Терентьев:** «Шкуры сняты, дефекты найдены, документы на месте. Теперь у суда есть на что опереться».
- Затем финальный экран (раздел 8).

### 7.4 Ограничения на тексты

- Не упоминать реальные дела, компании, суды, судей и клиентов.
- Не давать юридических гарантий («точно выиграете суд»).
- Никаких данных из внутренних материалов VETA (часть из них под NDA). Все кейсы собирательные.

## 8. Финальный экран и лидогенерация

- **Итог:** очки, найденные дефекты (X из Y), собранные документы (X из 9), побеждённые волки, «ложные подозрения».
- **Оценка по документам:**
  - 9/9 — «Дело собрано идеально»;
  - 7–8 — «Позиция сильная»;
  - меньше 7 — вариант недоступен, игрок не дошёл бы до победы.
- **Призыв:** «Ваш спор — не игра. Эксперты VETA проверят объект и документы до суда».
- **Кнопки:**

## 9. Экраны и меню

1. **Загрузка** — прогресс-бар в фирменных цветах.
2. **Титульный** — название «Прораб против волков», подзаголовок «Игра от Экспертной группы VETA», кнопки «Играть», «Как играть», «Звук», переключатель «Лёгкий режим». Угловые рамки обязательны.
3. **Как играть** — управление и правило «Срывай шкуры, собирай документы».
4. **Интро-комикс** — можно пропустить кнопкой.
5. **Уровни 1–3** с карточками «Совет эксперта» между ними.
6. **Пауза** — продолжить, рестарт уровня, звук, выход в меню.
7. **Финальный экран.**

**HUD:** каски слева сверху, папка документов по центру сверху, счёт справа сверху. Шрифт крупный, читается на телефоне.

Прогресс (пройденные уровни, лучший счёт) сохраняется в `localStorage` с обработкой ошибок. Если хранилище недоступно, игра работает без сохранения.

## 11. Чего не делать

- Не использовать персонажей, похожих на известных героев мультфильмов и игр, в том числе классического мультяшного волка. Все персонажи оригинальные.
- Не перерисовывать и не модифицировать логотип VETA.
- Не использовать образы других реальных людей, кроме А. Терентьева (на его образ согласие есть).
- Не брать данные, документы и названия из реальных проектов VETA.
- Не подключать внешние сервисы, трекеры и CDN в итоговую сборку.
- Не делать сцен насилия: волки убегают, а не погибают.

## 12. Этапы и критерии приёмки

После каждого этапа Claude Code делает сборку, коротко объясняет простым языком, что сделано, и даёт список «что проверить».

| Этап | Содержание | Критерии приёмки (проверяет заказчик глазами) |
|---|---|---|
| **1. Каркас** | Проект, Vite, сборка в один файл, сцены-заглушки, фирменная палитра, CornerFrame, титульный экран | `dist/index.html` открывается двойным кликом; видно титульный экран с рамками в правильных углах; кнопка «Играть» ведёт на пустой уровень |
| **2. Герой и управление** | `make_sprite.py`, спрайт героя с головой из фото Терентьева, портрет для диалогов, бег, прыжок, луч, сенсорные кнопки, камера | Герой узнаваем и выдержан в фирменной палитре; бегает и прыгает на клавиатуре и на телефоне; луч виден; управление отзывчивое |
| **3. Уровень 1** | Карта, волки-субподрядчики, маскировщик, документы, дефекты, чекпоинты, Ворота суда, обучающие подсказки, HUD | Уровень проходится за 2–3 минуты; шкуры срываются; документы появляются в папке; ворота не пускают без документов |
| **4. Уровни 2–3** | Каркас, сметчики, краны, сметные стены; отделка, подтопление, нотариальный протокол | Оба уровня проходятся; вода поднимается и останавливается при находке дефекта трубы |
| **5. Босс и финал** | Босс с двумя фазами, проверка пакета документов, финальный экран, CTA, поделиться | Босс побеждается только с полным пакетом; при неполном звучит реплика и возврат к чекпоинту; финальный экран показывает итоги и кнопки |
| **6. Сюжет и звук** | Интро-комикс, карточки советов, диалоги из `ru.json`, звуки, пауза, сохранение прогресса | Все тексты читаются и берутся из `ru.json`; звук выключается; прогресс сохраняется между запусками |
| **7. Полировка** | Баланс сложности, лёгкий режим, оптимизация, проверка на телефоне, `README.md` | Полное прохождение 7–10 минут; 60 FPS на ноутбуке; файл не больше 5 МБ; README понятен без программиста |

**Прототип для показа руководству — этапы 1–5.** Этапы 6–7 выполняются, только если прототип одобрят и решат готовить публичную версию.
