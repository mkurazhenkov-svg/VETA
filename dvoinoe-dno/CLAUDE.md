# Двойное дно. Дело о фальшивых четвертных — правила проекта

Изометрический диалоговый квест музея «Двойное дно» и кафедры судебной экспертизы.
Полное ТЗ: docs/TZ.md. Текущий этап: docs/STATUS.md.

## Команды
pnpm dev | pnpm build | pnpm test | pnpm e2e | pnpm validate | pnpm lint

## Инварианты (не нарушать)
- src/domain не импортирует pixi.js, preact, inkjs и DOM (ESLint это проверяет).
- Состояние меняется ТОЛЬКО через dispatch(Intent) → perform → GameEvent → reduce. Журнал — источник истины.
- Случайность только через rng из состояния; броски пишутся в журнал.
- Ключевая улика НИКОГДА не заперта только за броском: всегда есть путь через методичный осмотр.
  Это проверяет тест «идеальный обход» (tests/domain/core.test.ts).
- Броски не влияют на оценку — только решения игрока (tests/golden).
- Учебный и музейный контент (правила, веса, улики, тексты, экспонаты) — только в content/.
- Сцена = scene.json (мировые координаты в аршинах) + живопись. Код не знает координат предметов.

## История и право
- Не придумывай исторические факты, нормы Устава 1864 г. и УПК РФ, описания кредитных билетов.
  Нет данных — TODO(кафедра) или TODO(музей) в YAML + пункт в docs/OPEN_QUESTIONS.md.
- Игра не описывает технологию изготовления подделок: предметы — улики и колорит.
- Изображения денежных знаков — только стилизованные исторические, с пометкой «игровой реквизит». Современных — никогда.
- Люди и адреса вымышлены.
- Стиль «в духе Disco Elysium»: не копировать его ассеты, шрифты, названия навыков и интерфейс 1-в-1.

## Качество
- Новая логика в domain = новые тесты. Изменение оценки = обновить tests/golden и объяснить в CHANGELOG.md.
- Перед завершением задачи: pnpm lint && pnpm test && pnpm validate && pnpm build.
- Ассеты и библиотеки — только с совместимыми лицензиями, запись в ASSETS.md / THIRD_PARTY.md.

## Работа по этапам
- Работай только в рамках текущего этапа из docs/TZ.md, раздел 9.
- В конце этапа обнови docs/STATUS.md: сделано / известные проблемы / как проверить руками.
- Для визуальных этапов (M1, M3, M7, M8) прилагай Playwright-скриншоты ключевых экранов (docs/screenshots, `pnpm e2e`).
