# «Первый осмотр» — демо-прототип

Браузерный учебный симулятор осмотра места происшествия для студентов-криминалистов.
Вертикальный срез по ТЗ: **пролог «Дежурная часть» → Эпизод 1 «Квартира» → эпилог «Кабинет» → разбор**.
Дело «На Заречной», вариант истины «А — инсценировка племянником». Город, люди и события вымышлены.

## Как открыть

**Без установки:** откройте файл `dist/index.html` двойным щелчком (Chrome, Edge, Яндекс Браузер, Firefox; нужен WebGL2).
Всё внутри одного файла (~0,7 МБ): код, сцена, текстуры. Интернет не нужен.

**Для разработки:**

```bash
cd pervyi-osmotr
npm install
npm run dev      # локальный сервер с горячей перезагрузкой
npm test         # юнит-тесты домена и «золотые» журналы
npm run build    # сборка в один файл dist/index.html
```

## Управление

| Действие | Клавиша |
|---|---|
| Ходьба / обзор | WASD / мышь (щёлкните по сцене, чтобы захватить курсор) |
| Осторожный шаг / присесть | Shift / C |
| Действие с объектом, разговор | E (в меню — цифры 1–9) |

| Чемодан | Tab |
| Пауза | Esc |

## Что есть в демо

- **Пролог:** сообщение КУСП, указание дежурному об охране, состав СОГ (специалист приносит свой чемодан,
  оперуполномоченному можно поручить обход), комплектование чемодана из 32 предметов с лимитом 28 мест.
- **3D-сцена** в cel-shading (toon-материалы + контурная обводка): подъезд, прихожая, санузел, кухня, комната, балкон.
  Геометрия в метрах, все объекты процедурные — без сторонних ассетов.
- **Подготовительная стадия:** основание осмотра жилища, понятые или видеофиксация, вступительное слово,
  перчатки/бахилы/маска, охрана места, звонок фельдшеру.
- **16 объектов:** 13 улик Эпизода 1 (осколки, снег, замок, след обуви, пятна на тумбе, окурок, вторая чашка,
  пыльный контур, нетронутые ценности, следы пальцев ×2, квитанция ГСК, телефон) и 3 ложных следа
  (бинт медиков, следы ботинок и вода от участкового).
- **Скрытые следы:** след обуви и пыль — только в косом свете фонаря; квитанция — присев и с фонарём;
  потожировые следы — УФ-осветитель или фонарь вплотную, затем порошок (мини-игра опыления, матрица «порошок × поверхность»).
- **Фотосъёмка:** 4 вида, зум 24–105 мм; кадр оценивается по метаданным — доля объекта в кадре, масштабная линейка,
  номерной указатель, угол оптической оси, перекрытие. Галерея и фототаблица.
- **Хрупкие зоны:** шаг на след у тумбы или на балкон без мостков уничтожает улики; на снегу остаются ваши следы.
  Открыть балконную дверь до обработки шпингалета — смазать следы пальцев.
- **Мастер изъятия:** способ → упаковка → пояснительная надпись; реестр изъятого.
- **Опрос:** 4 человека (соседка, участковый, фельдшер по телефону, племянник приезжает по таймеру в 08:40),
  комиксные портреты с 6 эмоциями, доверие, предъявление фактов из блокнота, наводящие вопросы «загрязняют» показания,
  давление и угрозы, ловушка «забрать кроссовки», черновик объяснения.
- **События по таймеру:** соседка заходит в квартиру, если охрана не обеспечена; разряд видеокамеры (~40 мин без запасного аккумулятора).
- **Эпилог:** фототаблица (порядок от общего к частному), протокол (вводная часть из журнала, блоки описания
  с выбором формулировки, изменения обстановки, предъявление изъятого), версия и факты в её обоснование, назначение исследований.
- **Разбор:** 100 баллов по 5 критериям ТЗ, потолки за критические нарушения, исходы А/Б/В/Г, карточки нарушений
  с объяснением, карта осмотра (маршрут, точки съёмки, статус улик), лента сессии, раскрытие истины,
  экспорт журнала в JSON с контрольной суммой, печать.
- **Режимы:** «Обучение» (подсказки наставника и мгновенные предупреждения о нарушениях) и «Экзамен».

## Архитектура

```
src/
  content/   учебный контент: улики, диалоги, правила и веса, пороги кадра, техника, геометрия
  domain/    чистая логика без three.js и DOM: журнал событий, редьюсер, оценка кадра, правила, баллы
  render/    three.js: процедурная сцена, toon + outline, FPS-контроллер, инструменты, метаданные кадра
  ui/        HUD, меню, мастер изъятия, диалоги, планшет, эпилог, разбор
tests/       юнит-тесты домена и золотые журналы («отличник», «туннельное зрение», «процессуальный провал»)
```

Главные принципы из ТЗ соблюдены: **журнал событий — единственный источник истины** (любая сессия
воспроизводится детерминированно), рендер сообщает только факты, решения принимает `domain/`,
весь учебный контент — в `content/`, а не в логике.

## Отличия от полного ТЗ (упрощения прототипа)

- Контент лежит в JS-модулях `src/content/*.js`, а не в YAML + zod; диалоги — в JS-структуре, а не в Ink.
  Структура полей повторяет образцы из ТЗ, перенос в YAML/Ink механический.
- JavaScript вместо TypeScript, без Preact — чтобы прототип оставался маленьким.
- Один вариант истины из трёх; нет повтора момента в 3D (журнал для этого уже готов), PDF — через печать браузера.
- Нет редактора план-схемы (вместо него — привязки рулеткой к ориентирам и карта в разборе), 3D-сканера, Эпизода 2,
  режима преподавателя, point-to-move.
- Объяснение не редактируется, только просматривается и подписывается.

## Что должна проверить кафедра

Все методические решения — черновик. В `src/content/rules.js` у каждого правила поле `source` = `TODO(кафедра)`.
Особенно: верное основание осмотра жилища (в демо — ч. 5 ст. 165 УПК, помечено «черновик»), действия с обувью
племянника, матрица порошков (`SURFACES` в `evidence.js`), пороги кадра (`PHOTO_RULES`), правила упаковки, веса критериев.
